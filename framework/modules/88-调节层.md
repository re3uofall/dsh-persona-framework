# 88 · 调节层

> 一句话：**前三层默认不读字，只有这一层要让人格知道——因为它就是「我自己在调我自己」。**

## 一、它是什么

四层的最后一层：**元胞（归类）→ 组织（聚合）→ 功能（做事）→ 调节（反过来改前三层）。**

**它跟前面三层不一样的地方只有一条**：**它可以说话。** 前三层改状态、落账、一个字不给人格；调节层得让人格知道「我在调」——**不知道自己被调，等于没在调。**

## 二、结构

**四条职责，一条一个入口：**

| 职责 | 管什么 | 入口 |
| --- | --- | --- |
| **主体调节** | 谁在调、调多大范围 | `on` / `canAffect` |
| **价值调节** | 什么更重要 | `setWeight` |
| **批判调节** | 这一条对不对 | `shouldReview`（抽样） |
| **反馈调节** | 稳 / 进 | `feedback`(ok) |
| **代谢调节** | 收／丢／额度 | `assimilate` / `dissimilate` / `energy` |

落点：`.persona-framework/调节.json`

**但上面那张表只说「打算有什么」，不说「跑没跑」。** 真正的状态在下面这张，判据只有一条：**有没有调用点。**

| 能力 | 谁调它 | 状态 |
| --- | --- | --- |
| `setWeight` | `12c rankGaps`（权重真改排序） | **在跑** |
| `readVerdicts` | `调 sub=翻` | **在跑** |
| `suspects` | `调 sub=存疑`＋元胞自己写嫌疑 | **在跑** |
| `clearSuspect` | `调 sub=无疑` | **在跑** |
| `overrideVerdict` | `调 sub=改判`＋元胞判类时读 override | **在跑** |
| `dropOverride` | `调 sub=撤回` | **在跑** |
| `shouldReview` | `tick()` 出口：按 `reviewRate` 抽样，命中说「该复审」 | **在跑** |
| `assimilate` | `tick()` 出口：这一轮收进几条 | **在跑** |
| `dissimilate` | `tick()` 出口：这一轮挡出几条，不删记录 | **在跑** |
| `feedback` | `tick()` 出口：卡住就推远，没卡就往 1 拉 | **在跑** |
| `energy` | `tick()` 出口：这一轮用了多少 | **在跑** |
| `adjustStep` | `tick()` 出口：**开着才说话**，关着一个字不给 | **在跑** |

`on` / `canAffect` / `reviewRate` / `budget` 各有去处：`on` 管 `adjustStep` 说不说，`reviewRate` 管抽不抽，`budget` 是 `energy` 的分母，`canAffect` 只做标记。

**挂点在 `tick()` 出口，不挂在任何一步上。** 这条是硬的：调节层管的不是「起念那一步」，是「这一轮」。挂在 12a／12e／99 上，换个档位、换条流程就漏一截——低档只跑三步，那三步之外的判断就再没被回看过。挂在一轮的出口，跑三个 system 和跑十四步，都是同一圈。

判据：**把任何一个 system 从流水线里拿掉，调节层该照样跑。** 拿不掉，说明它挂错地方了。

**关档连调节都不跑。** 「关」就是关——不留一条「反正它不占地方」的缝。`off` 档 `systems: []` 曾被读成「不过滤」而全跑，那是把空集当成了默认值；现在显式写着 `still`。

**判过的记下来，下一轮不重判**——这四样（同化、异化、抽样、能量）都落在 `调节.json` 里，翻得到。

**照这张表查东西**：谁调它、在哪一步调。写「在跑」却找不到调用点的，就是拿一句整齐的话顶替一层真实结构——本模块自己反对的那种。

## 三、怎么动

**先说清楚它是什么：调节层是指令层，不是默认流水线。**

元胞、组织、功能三层默认跑，不问它。调节层不一样——**它要人开口才动**。它平时沉默，一旦认定「刚才那条判错了」，就伸手进去改。

### 第一步永远是翻，不是改

**它先得知道自己哪些判断被功能代替了。**

判据只有一条：**这一条它自己没插过手，是元胞按来源直接归的类。** 账本里没有改判记录的，就是代判的。

翻到的东西长这样：一条原话、元胞判的类（从哪来、是什么、多硬、归谁）、判了几次。

**翻不出这些，就没有「改」的立足点**——只能从头再判一遍，那是重算，不是复审。

### 它怎么知道元胞错了——不用感觉，用记号

**「觉得判错了」不是理由。** 得有一样指得出来的东西，否则每次重判都变成重算一遍。

元胞自己留四种记号，挑出来就是存疑：

| 记号 | 说它什么 |
| --- | --- |
| **前后判得不一样** | 同一句话，这轮判成愿望，上轮判成代价——它自己不一致 |
| **没判出来** | 判成了「说不清」——它没归进任何一类 |
| **改过又撤** | 改判之后又撤回，来回一趟 |
| **称不过** | 称重卡住，走不下去 |

**存疑不改判定。** 它只把这几条挑出来摆着，改不改是下一步的事。

还有一条最轻的：**认下「没判错」也留痕。** 划掉嫌疑不等于什么也没发生——那是「我看过、我认了」的证据。
### 第二步才是改

改的是判定，不改事实。事实在原来的地方；这里只动「怎么看它」。

三道硬约束：

- **要写 why。** 没理由的改动不算数，直接拒。
- **改了留着。** 谁改的、什么时候、改成什么——下一轮元胞先读它，读到就用它。
- **撤也要留痕。** 撤回不是抹掉，是记一笔「我改回来过」。

### 权重改的是先后，不是称没称过

**称重问的是事实**（有没有想要、有没有代价），权重改不了事实。
**决断问的是先后**（先做哪件），那才是权重该开口的地方。

把权重接到称重上，等于拿「我觉得它不重要」去改「它到底称没称过」——那是造假。

**权重归这儿，一条也不许散在别处。** 存在 `调节.json` 的 `weights`，改要写 why（凭什么压它），
看要看得到每一条的值和理由。散出去就没人说得清「这个 0.2 是谁定的」。

三层排下去，顺序不许倒：**硬的先走 → 同一层看权重 → 还平看提过几遍**。

**权重压不过硬的。** 硬的是「过线了」，权重是「我更想先做它」；让权重压过硬的，等于用偏好改期限。

### 它不动默认

**这条最容易被越过去。** 调节层能改一条判定，**改不了「元胞还跑不跑」**——那归总开关管，归人。

自己把默认那条路关掉，等于把自己坐的那根椅子锯了。

### 它不改功能的实现方式

这条比「不动默认」更窄、也更硬，两个常被搅成一堆：

| 想改的 | 归谁 |
| --- | --- |
| **这一条算什么**（愿望？代价？有由头？） | **调节层** |
| **功能怎么跑**（换判据、改参数、加一条补充、动代码） | **功能自反** |

**调节层碰的是标签，碰不到实现。** 它能说「这条判错了」，不能说「把元胞的判据改一改」。

为什么分这么死：**改判定是往外看，改实现是往里改。** 往外看错了可以再改回来；往里改，改的是下一次所有条目都走的同一条路——那一步不该由一个只看见单条的层去动。

真想改实现，路是那条：「写 `.persona-framework/功能补充.json`，下一轮读键」，或者由人改代码。**那条路不归调节层。**

### 一句判据

**调节层动的是标签，不是流水线。** 它能说「这一条看错了」，不能说「以后都别看了」。



1. **开**：`cmd sub=调` 带 `sub=on`；或 `framework_program op=impl id=88`
2. **改权重**：`cmd sub=调`，参数 `sub=weight key=<缺口名> w=<数> why=<为什么>`
3. **看状态**：`cmd sub=调`（不给 sub 就是看）
4. **反压前三层**：`canAffect` 开着才生效——**默认关**

## 四、判据

1. **调过之后，前三层的判断变没变？** 没变，那就是白调。
2. **改的时候留了「为什么」吗？** 没留的，是偏爱不是调节。
3. **抽样的比例是多少？** 全审会炸，全不审等于没有。

## 五、边界

- **不动人格文件。** 调节只改「功能怎么看」，不改「我是谁」——那条线归自我反写。
- **不每步都调。** 确定的直接过，只有「没底」的才送审。**全审会炸。**
- **不删。** 异化只记「这条不再用」，不抹；抹了就回不来。
- **默认全关。** 开不开由人说，不由它自己开——**它自己开自己，那叫跑飞。**

## 六、接口

- **上游**：前三层交下来的不确定（元胞判得没底、组织聚得含糊）
- **下游**：前三层的权重／路由／要不要审
- **人格**：注入里能看到「调节：开｜改过 N 条」，**看不到理由**（理由在账里，谁查谁看）
- **设置页**：单开一个「调节」，用来给权限、改比例

## 七、自查

- 关着的时候，人格那边看得到它吗？——看不到，那才叫关。
- 开着的时候，它改动了什么，说得出吗？
- 抽样的那个键，跑两次抽的结果一样吗？（不一样就是随机的，那没法复现）
