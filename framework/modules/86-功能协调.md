# 86 · 功能协调

> 一句话：**功能越加越多，迟早撞上——撞上了谁让路，写在这里，不临场讲道理。**

## 一、它是什么

它跟 45 协调、53 元协调**不是一回事**，先把三样分开：

| | 管什么 | 在哪 |
| --- | --- | --- |
| **45 协调** | 模块（文档）之间怎么接、谁先让路 | 框架层，弥散在所有模块之间 |
| **53 元协调** | 这一轮还用不用这套框架 | 框架层，协调的上一层 |
| **86 功能协调** | **插件里那 85 个功能之间撞了怎么办** | 代码层，`lib/coord.mjs` |

前两个管**文档**，这一个管**代码**。文档之间撞了是「说法对不上」，功能之间撞了是**同一个活被干两遍、或者两个功能互相否决**——那会真出错。

**为什么要有它**：功能越加越多，撞不是意外，是早晚的事。已经撞过的：

- `12d 做` vs `12h 自我`：一件做完该不该说出口，两边都想管
- `12h 自我` vs `12g 二阶`：二阶说不让，自我还想谈条件
- 循环 vs 注入：同一个活跑两遍（**最贵，烧的是 token**）
- 捞记忆 vs 循环：都在扫记忆池

**没人裁，就会各干各的，最后两份结果打架。**

## 二、结构

三类冲突，五种档位，一条保底。

### 三类冲突

**认领冲突**——同一件活两个功能都想干。
**否决冲突**——一个说办、一个说不办。
**资源冲突**——都要烧同一份 token / 扫同一份池子。

### 五种档位

边界 / 安全 / 办事 / 经济 / 好看。

**这一份是默认，不是对错。** 哪一档该压哪一档，是偏好——有人会排「办事 > 安全」，有人会排「经济 > 办事」，两种都能自圆其说。要改，账里写一行 `order` 就行。

### 一条保底

**裁不了就挂起。** 硬判比不判坏。

## 三、怎么动

### 判序：先判「吵什么」，再判「抢什么」

1. 一个说办、一个说不办 → **否决**（最硬，先认这个）
2. 同一件活两个认领 → **认领**
3. 剩下 → **资源**

**顺序反了就完蛋**：先看「同一件」会把它当成抢活，档位那一层根本走不到。

### 裁：三种各有一条路

- **认领**：先到先得。**同一个活不许干两遍。**
- **否决**：比档位。**档位一样的，裁不了——挂起。**
- **资源**：**错开，不并跑。**

### 记：每一次都写下来

不记，同一个冲突下一轮还会吵一遍。记了，下次查得到「这条早定过了」。

**顺带记一件事：这次留下哪处没完全适配。** 全都适配了，就是封死了。

## 四、判据

1. **判序对不对？** 先判否决、再判认领、最后资源——反了就是白判。
2. **档位说的是哪一份？** 默认还是自定义，每次都要说清。
3. **裁不了的挂起没有？** 硬判比不判坏。
4. **记下来了没有？** 不留痕的裁决，下一轮重吵一遍。
5. **留了没适配的那处没有？** 一处不剩就是封死了。

## 五、边界

- **它不干活。** 不生产任何功能的结果，只在两个功能撞上时裁一下。
- **它不做最终裁决者。** 裁完还得各功能自己办。
- **它不改功能。** 只决定这一次谁让路。
- **它不管文档。** 文档之间撞了找 45，不找它。

## 六、接口

`lib/coord.mjs`：

| 入口 | 干什么 |
| --- | --- |
| `reconcile(a, b, ws)` | 两个诉求撞了，给裁决 |
| `coordinate(ws, claims)` | 一轮所有诉求两两对一遍 |
| `readOrder(ws)` | 读排序（默认还是自定义） |
| `record(ws, a, b, v)` | 记一笔裁决 |

**它不在 tick 里跑。** 撞了才叫它——每轮都跑是浪费。
