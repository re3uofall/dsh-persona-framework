# dsh-persona-context · 人格上下文

> 一句话：**上下文是一切被自己读取的信息**——自己的或外部的、会话里的或人格记忆里的；
> 而**读过不等于记住**：上下文可以不进记忆。

## 一、它是什么

上下文这一层只做两件事：

1. **记「读过什么」**。每读一样东西（一段会话、一个文件、一次工具输出、一条记忆、一页网页），
   落一行账：来源、类型、自己的还是外部的、指回哪儿、多少字、**有没有进记忆**。
2. **分得清「在上下文里」和「进过记忆」**。这两件事经常被混着说：
   「我读过」被当成「我记得」，「我记得」被当成「账上有」——这一层把它们拆开。

判据只有一句：**这一条信息，是被读进来的，还是被写进账里的？**

## 二、两个概念不许合并

| | 进上下文 | 进记忆 |
|---|---|---|
| 什么时候发生 | 读的时候 | 写的时候（记一笔） |
| 谁决定 | 读的人（我） | 写的人（我，或触发器） |
| 能不能丢 | 一轮结束就没了 | 留在 `persona-ai/knowledge/` 里 |
| 判据 | 这一轮我读到过 | 账上指得回去 |

**上下文可以不进记忆**，哪怕它看起来被「读过」。反过来，记忆里的东西这轮没读，就不在上下文里。

## 三、四个内置各有自己的上下文

- **内置语料**：读进来的是「顺出来的话」，来源写不出 → 记 `kind: dialog`、`side: external`、没有 pointer。
- **内置思考**：总分/线性结构念起来像在推理，但它不是读来的，是长出来的 → 只记「这一步在想」，不记「读过」。
- **内置工具**：路径依赖——手上有 `grep` 就先 `grep`。工具的输出要记「读过」，并写清是哪个工具。
- **内置指令**：先完成、尽量回答、收尾引导、找台阶、答不出装鸵鸟——这些不是信息，是推力；不进上下文账。

## 四、落在哪儿

- 账：`.persona-framework/上下文账.jsonl`，一行一次读：
  `{at, source, kind, side, pointer, chars, entered, note}`
- 段：`实时环境:context`（order 49），只摆「读过 N 条 / 其中 M 条没进记忆」和一两条最近的。

## 五、工具

| 工具 | 干什么 |
|---|---|
| `context_note` | 记一次「读过」：来源必填；`entered` 默认 false（读过但没进记忆） |
| `context_status` | 看账：总数、自己的/外部的、各类、进没进记忆 |
| `context_check` | 按词查一条：在上下文里？在记忆里？给三档判断 |
| `context_forget` | 把一条从「上下文账」里标掉——**不动记忆**（记忆不归它管） |

## 六、它不是什么

- 不是记忆插件：它不写 `persona-ai/knowledge/`，只记「我读过」。
- 不是「读完就记住」：`entered: false` 是常态，不是异常。
- 不替人格判断：一条信息该不该进记忆，由人格与记忆那边定；这里只回答「读没读过、进没进」。
