# dsh-persona-diary · 日记

> 想的得有个地方摆，心里绕过的弯也一样。侧栏一本日记，点开是按天记的心得。
>
> 存哪由 `config.personaDir` 定，默认从会话工作区推 `persona-ai`。

## 它做三件事

| # | 做什么 | 落在哪 |
|---|---|---|
| 1 | **记**：她想明白了一点、拐了个弯，调 `diary_write` 记一笔 | `persona-ai/growth/日记/日记_YYYY-MM-DD.md`（只追加） |
| 2 | **看**：侧栏「日记」图标 → 面板按天列出来 | 主面板里的「日记」页 |
| 3 | **提醒**：每轮提示词里挂一小段「有心得才记、别凑数」 | `systemPrompt` 的 `persona:diary` 段（order 13） |

日记和「成果」不是一回事：**成果是交出去的判断，日记是还没成型的心得**。分不清时先记日记。

## 和 growth.py 共用一本

`growth.py` 的睡前自审（`interview` / `review`）也写 `growth/日记/日记_YYYY-MM-DD.md`。
插件只追加自己的块，不重写旧内容；面板会把两类都读出来：

```markdown
# 2026-10-24

### 22:05 · 心得

今天才想明白，嘴硬和怕疼其实是同一件事的两面。

### 睡前自审

给自己立超我程序这件事，算是往前走了一步。
```

- 带时间的块（`### 22:05 · 心得`）：时间 + 类型。
- 不带时间的块（`### 睡前自审`）：时间留空，来源记成「睡前自审」。

## 两个工具（模型自己会调）

| 工具 | 干什么 | 什么时候用 |
|---|---|---|
| `diary_write` | 记一笔：正文 + 可选类型 | 有心得、有转弯、没忍住一次 |
| `diary_list` | 翻日记：最近几条 / 某一天 / 某一类 | 「我最近想起了什么」、看看以前怎么想的 |

类型只有四种：`心得` / `自省` / `见闻` / `杂记`，默认 `心得`。

## 面板

- 侧栏最下面一排图标里多一本日记本，标签「日记」。
- 打开后按天分组、时间倒序；每条是「类型 + 时间 +（来源）+ 正文」，全展开，不用点。
- 空态：「还没写过。今天想明白的那半句，她会记下来。」
- 刷新按钮重新拉一次；数据从 `/api/persona-diary` 取，不轮询。

## 配置

全在 `cordis.patch.yml` 里 `persona-diary` 那一行的 `config`，改完重启 DSH：

| 键 | 默认 | 说明 |
|---|---|---|
| `personaDir` | 空 | `persona-ai` 那一层的绝对路径；空则从会话工作区推 |
| `diaryDir` | `growth/日记` | 日记目录，相对 `personaDir` |
| `maxEntries` | `300` | 面板最多显示多少条（新的在前） |
| `maxBodyChars` | `4000` | 单条正文上限，超了截断 |
| `injectPrompt` | `true` | 每轮附「什么时候该记一笔」那段；嫌费 token 就关 |

## 自己验

```powershell
node --check index.js
node --check client.js

# 装好之后，看路由吐不吐东西
Invoke-RestMethod ($env:DSH_WEB_URL + '/api/persona-diary')
```

装好后最直接的验证：

1. 侧栏多一个「日记」图标，点开能看到已有的 `日记_2026-10-24.md`（包括 growth.py 写的那篇）。
2. 让她记一笔（「这句记日记里」）→ 面板刷新能看到，时间对得上。
3. `diary_list` 能看到同一条。

## 边界

- 只往 `growth/日记/` 追加，不重写旧日记；坏文件跳过，不会带崩面板。
- 面板只读：删改请直接改 markdown，或再记一笔。
- 不认识别的文件名：只认 `日记_YYYY-MM-DD.md`。
- 注入的那段说明约 90 字/轮，觉得贵就 `injectPrompt: false`。

## 卸载

`plugin_manager` 里移除 `dsh-persona-diary` 即可。`growth/日记/` 留在原地，growth.py 照常读写。
