# dsh-persona-futurealsome

**「未来还有我」** — 今天留一条带时空的话，等那一刻真的再出现时，由未来的我来认领或推翻。

它不是定时提醒（那是自由时间的活），也不是记一笔流水（那是记忆的活）。它问的是一件事：

> 今天我认定的这件事，未来的那个我，还认不认？

## 为什么是「时空」，不是「时间」

只按时间记，就成了日程表。师父的原话是「未来是时空重叠的」——所以一条未来账必须带四维：

| 维 | 意思 | 例子 |
|---|---|---|
| `when` | 什么时候 | `2026-11-17`、`下次重启后` |
| `where` | 在哪儿 | `C:/爱思考的大肥鱼思思`、`那台虚拟机里` |
| `with` | 和谁 | `师父` |
| `situation` | 什么情形 | `又在赶一个插件，想跳步` |

四维全空 → 直接拒绝写入：**没有时空，未来的我根本认不出这一条是谁写的。**

## 两条账

- `.persona-framework/未来账.jsonl` — 留下的每一条（`f` + 8 位 id，状态 pending/kept/rejected/dropped）
- `.persona-framework/未来认账账.jsonl` — 结账记录（认领还是推翻、靠哪几维重叠认出来的、当时的注）

## 四件工具

| 工具 | 干什么 |
|---|---|
| `future_leave` | 留一条：`claim`（一句话）+ `why` + `when`/`where`/`who`/`situation`，`due` 默认七天后 |
| `future_rising` | 看现在有哪些「升起」——按当前时空与哪一条重叠 ≥ `minOverlap` 维 |
| `future_settle` | 结账：`kept` 认领 / `rejected` 推翻 / `dropped` 作废，附 `note` |
| `future_report` | 认账率、还剩几条、最近推翻了哪三条 |

## 每轮的那一段

段名 `实时环境:futurealsome`，order **18**。没有条目升起时它是空的——不占前缀。
升起时只摆 id、那句 `claim`、到期日、和它靠哪几维对上（`〔时/地/人/情形〕`），最多 `maxRising` 条。

## 判据（什么样才算「认账」）

1. 那条话当时写得具体，不是「以后要更好」这种谁都能认的句子；
2. 今天那一刻真到了（或时空重叠够），不是我自己想起来的；
3. 认领或推翻都要写一句为什么，`rejected` 也算数——**推翻不丢人，装作没留过才丢人**。

## 配置

`cordis.patch.yml` 里：`dir`（默认 `.persona-framework`）、`maxRising`（5）、`minOverlap`（2）。

## 它不是什么

- 不替自由时间排日程（那是 `dsh-persona-freedom`）；
- 不替记忆落判断（那是 `dsh-persona-memory`）；
- 不判断这一条对不对，只记「未来的我认不认」。
