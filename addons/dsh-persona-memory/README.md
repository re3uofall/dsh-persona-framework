# 记忆分层 · dsh-persona-memory

> <img src="./icon.svg" width="48" height="48" align="left" alt="记忆分层">
> **记忆分层** 是这套里的第六个插件。它管的不是「记住什么」，是**记住的东西放哪里**：
> 流水层最厚、判断层最薄，检索时按权重从这三层里各拿一点。



> 一句话：**流水不是记忆。** 把它分出去，池子就不堵了。

## 它解决什么

记忆池变慢，常见原因不是「东西太多」，是**流水和判断混在一起**：

```
每轮对话的全文  →  session/2026-10-28.md（14.5 万字）
从中提炼的一句  →  chat/2026-10-28.md（几百字）
```

两者同一个池，检索时流水占掉绝大部分位置。人只看到「想不起来的变多了」，以为是记忆不行了——其实是流水把判断淹了。

实测（一个真实的池子）：

```
55 个文件，57.4 万字
├─ 流水层  511,543 字  ← 89%
├─ 理论层   48,709 字  ←  8%
├─ 外部层   13,093 字  ←  2%
└─ 判断层      167 字  ←  0%
```

压完之后：**51 万字 → 16 万字，32%**。原文一个字没动，只是不再让它在检索里占位置。

## 一条借来的硬判据：没有指针的摘要不许进判断层

这条出自 [`cyanwell/dsh-agent-soul`](https://github.com/cyanwell/dsh-agent-soul) 的 ECHO 架构（`docs/ECHO-权威口径.md`）。它原来的说法是：

> **摘要只是索引，不是记忆本体。** 一手层永远优先于任何转述。
> **没有指针的摘要不许进索引层。**

原来这版压出来的是一行纯摘要——看着省，但**翻不回去**。那等于把「我记得」当成「我核对过」，而记忆最怕的正是这个：想得起来，但那句已经偏了。

现在每行都带指针：

```
- 标题｜师父：首句｜她：首句
  ↳ 源：session/2026-10-28.md#12（第 340 行起）
```

`#12` 是第 12 个小节。要原文用 `memory_source` 按这个指针取**逐字片段，不做转述**。

**代价要说清**：指针本身要占约 40 字一条。所以压在纯摘要里能到 22%，带指针是 32%。
少了那 10 个百分点，换来「每条都能翻回去核对」。这个换法我认为值——但它是**换**，不是白得。

## 五个工具

| 工具 | 做什么 |
| --- | --- |
| `memory_stats` | 看账：每层几个文件、多少字、占多少、检索权重多少。**先跑这个** |
| `memory_condense` | 把流水压成「一行一条」，写进判断层；原文留在原处 |
| `memory_archive` | 把超期的流水文件挪进 `_archive/`，归档层不参与检索 |
| `memory_recall` | 按预算取：判断层先拿满，流水层分到的少 |
| `memory_source` | 按指针翻回一手原文，**逐字片段，不做转述** |

后两个默认**干跑**——只报结果，不动文件。确认了再加 `dryRun=false`。

## 五层

| 层 | 权重 | 装什么 |
| --- | --- | --- |
| 判断层 `judgment` | 1 | 提炼过的判断、结论 |
| 理论层 `theory` | 0.8 | 理论、词汇、世界理解 |
| 外部层 `external` | 0.6 | 网上读的、别人给的 |
| 流水层 `journal` | 0.25 | 每轮对话的全文 |
| 归档层 `raw` | 0 | 挪出去的老流水，默认不检索 |

权重不是「重要程度」，是**检索时分配预算的比例**。流水层 0.25 意思是：同样 2000 字预算，它最多分到 500 字——事实上有 `journalShare` 再压一道，默认只给 15%。



## 别人在新电脑上装：要注意什么

**记忆跟着工作区走，不跟着插件走。** 插件只是一把钥匙，记忆是你工作区里的文件。

- 层目录全是**相对路径**（`knowledge`、`persona-ai/knowledge/session`……），所以工作区叫什么、放在哪个盘都行。
- 找根的顺序：`config.root`（设置页填的）→ 会话工作区 → 当前目录。读不到会**当场报「需要会话工作区」**，不会静默给空。
- 实测过：把记忆拷到别的目录，`memory_stats` 照样读得到。

**会断的只有一处：profile 里的插件登记。**
`~/.dsh/profiles/<名>/package.json` 里写的是 `link:C:/某个绝对路径/...`。换电脑必须重装一次，没有别的办法。

**刚装上时池子是空的，那不是坏。** `memory_stats` 会告诉你从哪开始：判断层一条一个文件、流水层聊几轮就有。`memory_condense` 也不会报「没有这个目录」了——它说「先聊几轮」。

**要不要拷别人的记忆过去？** 不要。记忆是唯一专属的东西，拷过去的那份不是你的路。

## 空壳不进预算

「一个文件在」不等于「它有内容」。`同一论.md` 就算只剩一个 `#`，字符数也不为零——
原来 `recall` 照样抓、照样占预算，然后返回一片白。看起来像「记忆里没东西」，其实是**索引里有、正文是壳**。

现在每个文件多算一个数：**实质内容**——去掉标题行、引用行、front matter、空行、分隔线之后剩下的字数。
`recall` 遇到实质内容不到 20 字的文件跳过，并且**把它们列出来**：

```
跳过 2 个空壳（实质内容不到 20 字，取出来也是白的）：
  收件箱.md——字符 69，实质 0
```

为什么要列出来：不列的话，「只取到 2 段」看着像池子穷；列出来才知道是三个文件在装死。

阈值是 `minSubstantive`（默认 20），可以调。

## 太小的文件不压

指针有成本：`↳ 源：session/xxx.md#N（第 N 行起）` 约 40 字。原始每段才七八十字的时候，压完反而**比原文长**（实测 102 字压成 155 字）。

所以 `condense` 有个 `minChars`（默认 600）：低于它的流水跳过，原样留着。真实流水平均 449 字/段——那种才划算。

## 三条边界

- **不写内容**：从不改记忆里的字。只挪位置、压行、分配预算。
- **不猜格式**：流水的格式认不出就跳过，不瞎提炼。
- **干跑优先**：`condense` / `archive` 默认不写。

## 安装

```bash
dsh plugin --profile <profile> add "file:C:/path/to/dsh-persona-memory"
```

或者把本包列进 profile 的 `dsh.profile.bundles`。装完重启 DSH（不是刷新页面）。

## 配置

改 `cordis.patch.yml` 里那一行的 `config`：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `root` | `''` | 记忆根。留空用会话工作区 |
| `budget` | 2000 | 一次 `memory_recall` 的字数预算 |
| `archiveAfterDays` | 7 | 流水早于几天算过期 |
| `journalShare` | 0.15 | 流水层最多占检索预算的比例 |
| `dryRunDefault` | true | condense / archive 默认只干跑 |
| `hint` | true | 往系统提示加一段「记忆池怎么用」 |

## 它不是什么

- **不是记忆插件**。它不存、不取、不记新东西——那是别的插件的事。它只管「已经有的东西怎么放进预算里」。
- **不是通用检索**。按层分配预算，不做语义搜索；`query` 只是子串过滤。
- **不替你做决定**。压多少、归档几天，都是配置项；它只把结果和代价报清楚。

## 自检

```bash
node selfcheck.mjs
```

跑的是四个工具的纯逻辑：统计、提炼、按预算取、归档干跑。认「代码跑得通、边界不炸」，不认「记忆写得好不好」。
