# dsh-persona-sweep —— 清扫（功能实现层）

功能实现层的第一个插件：**只改状态，不给人格字。**

它做的事只有一件：把 `<工作区>/.persona-framework/` 下那些账本（`*.jsonl`）压实——超过行数就把原账整份归档到 `_archive/`，只留尾部若干行；每次跑完往 `清扫账.jsonl` 记一行、往 `清扫账.json` 写状态。

## 为什么它算「功能实现」

按 `GUIDE-FEATURES.md` 的三条判据：

| 判据 | 这一件 |
| --- | --- |
| 改状态 | 账本被重写、归档文件多出来、`清扫账.json` 变了 |
| 不给人格字 | 没有注册任何 `systemPrompt.section`——一个字都不摆进上下文 |
| 下一轮真的变了 | 账本行数真的少了，归档真的在盘上 |

## 三个工具

- `sweep_status` —— 只读：现在多少本账、几本超阈值、上次什么时候跑的。
- `sweep_run` —— 真扫一次（可临时改 `maxLines`/`keepLines`），回这次归档了哪几本。
- `sweep_report` —— 列每本账的行数与字节，按行数降序。

## 触发器

`agent/pre-step`：每轮记一次会话工作区；冷却时间（默认 15 分钟）到了且没关，就真跑一次 `sweepAll`。

## 边界

- 只碰 `<ws>/.persona-framework/` 下的 `*.jsonl`，不碰别处。
- 归档不是删除：整份原账落在 `_archive/<名>.<时间戳>.jsonl`。
- 不重试、不猜：一本出错记 `{file, error}`，其余照跑。
